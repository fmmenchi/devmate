# ADR 0002 — An Nx workspace, on the shared-platform model

- **Status:** proposed
- **Date:** 2026-10-15
- **Deciders:** Fabio Menchicchi

## Context and problem statement

devmate is a TypeScript product: a CLI core, a VS Code extension later, and the contracts
between them. Fabio already runs that kind of workspace in `shared-platform`, with its own
tooling for documentation and CI. A third, different setup would be a third set of habits.

## Decision

**An Nx workspace, as in `shared-platform`.** pnpm workspaces, TypeScript project references,
Node ≥ 24. Every project is created by its official generator, never by hand; module boundaries
are enforced by tags. Tasks run through Nx (`pnpm nx …`).

**One gate, everywhere.** `pnpm run check` — format check, the Nx targets, and the skill gate
(ADR 0003). The `pre-push` hook runs it and CI runs it. CI has no gate of its own; it is only the
place where the gate cannot be skipped.

**Documentation is a Docusaurus site** at `apps/docusaurus`, generated by
`@fmmenchi/nx-docusaurus`. ADRs live in it, at `apps/docusaurus/docs/adr/`. A project's own
documentation lives in its `docs/` folder and is assembled into the site by the plugin.

**Commits and branches are enforced by hooks.** Conventional commits through commitlint on
`commit-msg`; semantic branch names `<type>/<kebab-description>[-<issue>]` on `pre-push`, with
the type vocabulary in `tools/commit/types.mjs` — the same list as `ai-skills` and
`shared-platform`. The `pre-push` check reads **the refs being pushed**, from stdin, not the
branch checked out: checking `HEAD` lets `git push origin HEAD:refs/heads/anything` through.
History is linear, and a human merges.

**CI uses `@fmmenchi/gh-actions` from `shared-platform`, pinned by commit SHA**, never by a
movable tag.

**Agent settings are tracked; agent state is not.** Tool configuration is committed (ADR 0001).
`.claude/worktrees/`, `.claude/settings.local.json`, `.nx/` caches and `.cache/` are ignored.

### What is not taken from `shared-platform`

- **Skills mirrored into every tool's folder.** The Nx generator writes the same skills into
  `.cursor/`, `.github/`, `.opencode/`. Here they have one source, `.agents/skills/`; Claude Code
  gets them from the Nx plugin enabled in `.claude/settings.json`.
- **A `pre-push` that checks the checked-out branch.** See above.
- **Nx Cloud.** Neither the generated CI nor the CI-monitoring skill that depends on it.

## Consequences

- `@fmmenchi/*` packages come from GitHub Packages, which requires a token even for public
  packages: `NODE_AUTH_TOKEN` from `GITHUB_TOKEN` with `packages: read` in CI, a PAT in
  `~/.npmrc` locally. The repository's `.npmrc` maps only the `@fmmenchi` scope.
- devmate depends on `shared-platform` (the docs plugin, the CI bricks) and on `ai-skills` (the
  skill gate). Each dependency is pinned; neither depends back.
- `nx release` is not set up: devmate publishes nothing yet.
