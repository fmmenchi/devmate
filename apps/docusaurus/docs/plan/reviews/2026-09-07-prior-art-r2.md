**How reviewers are launched/counted.** Launched as Claude Code `Agent` subagents (7 `*-reviewer` types, `effort: medium`, no `tools:` allowlist — "theatre with Bash, capability-destroying without", pinned by `hooks/tests/test_agent_definitions.py`), backgrounded, worktree-isolated, with a brief naming the base SHA; counted **from the roster file, never from memory** because on 2026-07-28 of three backgrounded reviewers one delivered only on request and two never did (`SKILL.md:84`). Measured over 420 launches / 78 sessions: median 2.0 min, p90 6.1, one 58-min run = 20% of all blocking time; worst sessions ran 8/13/15 rounds against budget 5 (`quality_reports/plans/active/2026-07-28_review-loop-cost.md:156-168`). A W0 audit found 84/84 background launches' findings were collected (strict attribution) before flipping the default.

**How score is computed.** Deterministic arithmetic over consolidated findings; the *model* still does the subtraction in `skills/score/SKILL.md:18-20` (only the history row is scripted). `pi-forge` moved this fully into code: `extensions/score.ts` runs `make check` then `make test-e2e` without a shell, `GateResult.status ∈ {pass, fail, missing, error, not-run}`, `computeStaticScore` returns `0` on any fail, `100` only if all pass, otherwise **`null` = inconclusive**; the report prints "Major findings: not evaluated" (`score.ts:35-41, 239-242, 342-343`); history under `.git/pi-forge/score-history.jsonl`, not the tree.

## Copy verbatim (5)

1. **Roster on disk at launch; count returns from files; join at consolidation, not FIX** (`SKILL.md:84`; `review-budget-guard.py:139-154`). Reason: the zero-findings path skips FIX, "which is exactly the path where a missing reviewer reads as clean"; observed 1-of-3 delivery.
2. **Two-confirmation gate with precise staleness**: a green verify must postdate both the last source edit and the last failed verify; a write-class subagent launch invalidates evidence; an evidence path must be in-repo, contain `metadata.json` (`sha, dirty, branch, per-step {command, exit, duration}`), mtime ≥ last edit; false claim blocks, infra error fails open (`score-evidence-guard.py:166-176, 181-211, 259-268`; real-evidence plan decisions 4, 9). Reason: "an evidence claim that is false is worse than none"; verified live 2026-07-28: fabricated → BLOCK, stale → BLOCK.
3. **Consolidation invariant**: dedup key `(file, line, normalized claim)`, keep highest severity, list every reporter, never merge distinct claims at one line, and **never tell a reviewer another one owns a concern** (`SKILL.md:86-94`; `2026-07-27_finding-dedup.md`). Reason: two Majors for one fail-open at `x.go:42` was −20; proved on its first live run (architecture + dx filed the same GOBIN bug).
4. **Missing gate is neither 0 nor 100**: `score` refuses; pi-forge `status: missing|error|not-run` and `score: null` (`skills/score/SKILL.md:65`; `score.ts:35-41, 239-242`); jidoka: no `done` from exit status, only a schema-valid result tool + settled event. This is D3 already built and tested.
5. **A reported literal/artifact is an interface; its parser ships in the same change**, and a truncated/capped reviewer becomes a **Major finding**, never silence; the cap is never told to the reviewer (`SKILL.md:178, 181`; `docs/solutions/debugging/2026-07-15_telemetry-signal-saturation.md`; LEARNING 2026-07-27 "who consumes this?"). Reason: 0 SCORE events across 6 sessions until the literal landed; an agent told its deadline "returns shallow findings fast, indistinguishable from diligence".

## Do not copy (3)

1. **Transcript-regex Stop hooks as the enforcement layer.** They parse an undocumented session JSONL (`LEARNING.md:96`), read only what the session self-reports, fire after the cost is spent, and cannot interrupt a running tool (decisions 13, 15). In devmate the loop is code: budgets, caps, and joins are `if` statements before launch, not regexes after.
2. **The fixed rubric numbers and model-side subtraction** (`quality-gates.md:8-40`; `score/SKILL.md:18-20`). −10/−3 and 80/90/95 were never calibrated (result rows: "insufficient data"), produced 27/100 on sound work, and the model still adds. Keep the *shape* (Critical ⇒ 0, deductions over consolidated findings, thresholds by intended action) but derive weights in Phase 5 and add only in code.
3. **The harness-invokes-itself product shape** (issue-loop as a skill inside a Claude session with `gh` and push rights; `pr-watch` as bash + `claude -p`). Max abandoned it for jidoka: credentials out of the model process (decision #10), no generic Bash (decision #46), engine-executed commands from a digest-frozen plan (decision #44), and a durable state machine with crash-window classification. The plan's "core is deterministic code" already points this way; do not let Phase 3 regress to "a skill that calls `gh`".

# C. What would change the plan (ranked)

1. **Plan:** "Implement: the project gate passes" / D4 "a wrong PR costs a review" / step 12 "opened as draft when score is below PR-ready".
**Evidence:** METR 2026-03: maintainer merge rate ~24.2 pp below the automated grader; even human golden patches re-accepted at ~68%; 2025-08: Claude 3.7 passed tests on 38% of tasks, "none mergeable as-is", testing gaps in 100%. AIDev: agent PRs "accepted less frequently", bug-fix and perf tasks merge worst, not-merged PRs touch more files.
**Change:** the rubric scores mergeability dimensions with evidence — test-file diff (added/modified/skipped tests), diff size vs plan, coverage delta, project lint — not gate pass alone; the Implement measure in the matrix becomes "merged unchanged / merged after N fix rounds / closed", and the eval set is stratified by issue type (bug-fix, perf, docs/CI). Always open as draft (SWE-agent, OpenHands, Copilot all do).

2. **Plan:** "step 7 … skill ×N … each reviewer sees the diff and nothing of the others"; step 8 groups and keeps highest severity.
**Evidence:** LLM code reviewers on *real* PRs: F1 ≈ 0.07 (0.847 on synthetic), near-zero recall on performance bugs, Haiku 4.5 beat Sonnet 4.6 at 3.2× cheaper (arXiv 2606.15689); consensus "popularity trap" amplifies shared errors unless reviewers are model-diverse (2510.21513); same-family generator/reviewer errors correlate (2603.25773); context separation *is* the mechanism, repeating self-review adds nothing (2603.12123). Max's fleet runs 7 same-family reviewers routed by file pattern; his cross-family review lives elsewhere (`/second-opinion`: Claude+Gemini+DeepSeek in Docker; `claude-advanced-review` with Semgrep as ground truth).
**Change:** roster entries carry `model_family`; at least one reviewer from another family (Codex adapter — this doubles as the D2 second-adapter proof); consolidation treats agreement as signal only across families; "zero findings" from N reviewers yields `review: not measured` unless each reviewer reports an evidence scope (files read, commands run — pi-forge's "not checked" field); the matrix includes small models for review.

3. **Plan:** "Parallelism is used in exactly one place, step 7, because adversarial review is read-only."
**Evidence:** Max's reviewers write by design — the PR #114 Critical came from 11 mutants written to hook source; "isolation, not permission" (`SKILL.md:170, 176`); `reviewer-isolation-guard` denies un-isolated launches; issue #118 shows a read-only downgrade silently degraded the evidence gate. Claude `--permission-mode dontAsk` still auto-approves the read-only command set; `claude -p --worktree` never cleans up. Codex offers OS-enforced `--sandbox read-only`.
**Change:** "read-only" means read-only **with respect to the main tree**: each reviewer runs in its own worktree copy (or Codex sandbox) where probes and mutation runs are allowed; the brief names the base SHA; findings anchor `file:line@sha`; consolidation checks the tree still matches; worktrees are removed only after consolidation and leftovers recorded. The adapter contract expresses the isolation *capability* (OS-enforced vs allowlist) instead of assuming parity.

4. **Plan:** D4 "Plan and merge. Everything between runs unattended."
**Evidence:** Every production system adds a **third gate: CI execution on agent pushes** (Copilot: workflows don't run until a human clicks "Approve and run workflows"; Codex documents a `contents:read` diff-artifact job separate from a `contents:write` apply job). Merge hardening: Copilot's own approval "won't count"; Anthropic's `agent-approval-check` requires N human approvals and invalidates on push. Max's data cuts the other way on the plan gate: wishew dropped it for simple/moderate with a falsifier and got 33/33 merged, 0 closed; jidoka makes the gate **conditional**: deterministic complexity ⇒ `complex` waits for `plan:approved`, `humanOwned` classes are never attempted; OpenHands/Codex gate at *action* level by risk.
**Change:** plan gate conditional on triage: simple/moderate run unattended to a draft PR, complex stops at the plan, hard-risk classes (security core, data-loss migration, release/tag, cross-repo, unverifiable) are triaged `human` and never planned; add explicit policy on CI trigger for agent pushes; ship a required status check (N human approvals, stale on push); keep an action-level allowlist inside the implement step — a phase gate doesn't replace it.

5. **Plan:** D2 contract "input: repo, issue, skill set, effort; output: artefacts directory, exit status."
**Evidence:** Claude `-p --output-format json` returns `{subtype ∈ success|error_max_turns|error_during_execution|error_max_budget_usd, is_error, structured_output, session_id, total_cost_usd (estimate), modelUsage, usage (excludes subagents), permission_denials}`; exit 143 on SIGTERM; auth failures print as `result` with exit 0-ish semantics; `-p` **without `--bare` runs the target repo's `.claude/settings.json` hooks and `.mcp.json` servers with no trust prompt**; skills are passed via `--add-dir`/`--plugin-dir`/SDK `skills:[]`, not a flag. **Change:** the adapter contract is event-level, not exit-code-level: `{session_id, terminal: success|max_turns|budget|error|killed, structured_output: validated against the step schema | absent, cost: {usd|tokens|not measured}, denials[], transcript_path}`; a missing/invalid structured output makes the step *not measured*/failed, never parsed from prose; the Claude adapter must run `--bare` and inject skills explicitly — isolation from the target repo's config is a security requirement, not a nicety (claude-code-action restores config paths from the base branch for the same reason).

6. **Plan:** "The coordination medium is the filesystem … every hand-off is inspectable, every step replayable."
**Evidence:** confirmed by OpenHands V1 (event-per-file after abandoning pub/sub; `flock` unreliable ⇒ single writer), SWE-agent (`config.yaml` next to `.traj`, idempotent re-runs), Max (immutable `NNN-findings.md` with `supersedes`), jidoka (single-writer actor, append-only transitions). **Change:** core is the sole writer of the run dir; reviewers write only their own subdir; step files are immutable (a later round writes `NNN+1` with `supersedes`); each step records the runner `session_id` so it can be resumed rather than replayed; `run.json` captures inputs so a run re-executes; every GitHub write is an intent file (`prepared → sent → attributed|escalated`) with read-back, and a lost response never triggers a blind re-create (PR create is not idempotent).

7. **Plan:** step 6 "fresh evidence or no claim"; step 11 "the model supplies measured values and nothing else"; D3 "absent evidence yields not measured".
**Evidence:** confirmed and already implemented (§A items 2, 4). 8. **Plan:** "triage is the router … RouteLLM … FrugalGPT"; matrix on "five to ten closed issues".
**Evidence:** RouteLLM trains routers on ~80k Arena preferences; FrugalGPT's cascade uses a trained scorer with learned thresholds — neither is a hand-written triage on 5-10 examples. Anthropic's research eval started at ~20 queries. Max: an eval "measured the author's machine"; denominator from answers received, not cases (LEARNING 2026-07-25).
**Change:** reframe D7 as a **cascade** (cheap first; triage `confidence: low` escalates — the `wishew:issue` thinking→thinking-deep shape) and cite RouteLLM/FrugalGPT as analogy only; sanitize the eval set (strip comments and linked PRs from the issue text; prefer issues closed after candidate models' cutoffs; add tests beyond the closing PR's); denominators are `len(cases)`; results stored with a schema so anyone can re-run and get the same number.

10. **Plan:** step 9 "loops to 6; bounded number of rounds".
**Evidence:** prose budgets ran 60-200% over; the Stop hook cannot prevent the cost; a synchronous `Agent` launch cannot be capped; cap must be harness-side and never told to the reviewer; truncation = Major finding; jidoka: 3 rounds, exhaustion **blocks** rather than weakens; Copilot hard-caps 59 min; OpenHands `max_iterations`/budget; Claude `--max-turns`, `--max-budget-usd`; Codex `timeout` at process level.

11. **Plan:** `reviewing-adversarially` "must not see the reasoning that produced the diff".
**Evidence:** Cognition principle 1 is "share context, share full agent traces" — its objection is to parallel *writers*; Anthropic best practices: reviewer "sees only the diff and the criteria you give it", and warns "a reviewer prompted to find gaps will usually report some, even when the work is sound"; Max gives reviewers plan + diff + base SHA + declared exclusions (page-fault rule, `SKILL.md:31`); pi-forge's artifact = diff + relevant context + requirements + **verification evidence**, with "not checked" listed rather than fetched.
**Change:** reviewer input is `plan.json` + diff + `verification.json` + declared exclusions (never the conversation); the finding contract requires `evidence` and `confidence`, reviewers instructed to flag only correctness/requirement gaps; each report carries an "evidence scope / not checked" section that feeds `not measured`; scoring weighs severity and evidence, not finding count.

12. **Plan:** step 13 "CI watch … no automatic action" and a dedicated `judging-ci-failure` skill.
**Evidence:** Max's post-PR loop contract was never exercised in 20 sessions; pr-watch reviews PRs but doesn't fix CI; Sweep's 10-attempt GHA fix loop is the cautionary shape; jidoka excludes CI management from V1; Copilot makes CI a human-approved event. OpenAI governance: legibility comes from "a ledger of actions taken", not retroactive explanation.
**Change:** demote step 13 out of Phase 3's exit criterion; core polls and writes `ci.json` with raw check results; a CI failure becomes a finding entering step 9 only on the human's request. Independently, the run dir should carry the tool-call ledger (commands, exit codes) per step — the adapters already emit it — rather than only the model's narrative.
